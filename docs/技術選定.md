# 技術選定

## 比較した構成

| 構成 | 利点 | 今回の判断 |
|---|---|---|
| Next.js + Cloudflare用アダプター | 認証・SSR・大規模な画面構成に対応しやすい | 端末内保存が中心の自分用ツールでは、サーバー描画とアダプターの保守が増えるため不採用 |
| React + Vite + Workers | 状態の複雑な画面や拡張に向く | 有力な拡張案。現時点ではビルドとランタイム依存を増やさずに必要機能を実現できるため不採用 |
| ブラウザ標準JavaScript + Workers | ビルド不要。静的配信と小さなAPIで動かせる | 採用。自分用・PC優先・入力と確認が中心のアプリに合わせた |

## 採用した技術と理由

| 技術 | 役割 | 選定理由・制約 |
|---|---|---|
| HTMLとJavaScript ES Modules | 画面・入力・採点 | 実行時の外部依存がなく、ファイルから処理の流れを追いやすい。画面が大規模化したらコンポーネント化の検討が必要 |
| CSS Grid / Flexbox | PC向けの複数カラムと小画面対応 | お題・入力・キラーワードを並べ、幅が足りない場合に縦へ再配置できる |
| CSS keyframes / transition | ボタン・キャラクター・通知・スケルトン | 大きなアニメーションライブラリを読み込まずに操作に反応する動きを実現。OSの「動きを減らす」に対応 |
| 手描きSVGとCSSキャラクター | アイコン・ポコ | 他社キャラクターの権利を使わず、解像度に依存せず描画。画像生成APIも不要 |
| Cloudflare Workers Static Assets | 公開画面の配信 | 画面とAPIを同じデプロイ単位にして運用を簡単にする。[公式](https://developers.cloudflare.com/workers/static-assets/) |
| Cloudflare Workers | 採点APIとAIへの窓口 | サーバー管理を減らし、Web標準のRequest/Responseで実装。ローカルテストに同じ処理を利用 |
| Workers AIバインディング | 任意のAIコーチ | 別会社のAI APIキーを管理せず、Cloudflareアカウント内で利用。[公式](https://developers.cloudflare.com/workers-ai/configuration/bindings/) |
| Qwen3 30B A3B FP8 | 日本語のコーチ文 | 多言語の指示追従を扱うCloudflareホストモデル。2026-10-20に[公式のモデル識別子と応答形式](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/)を確認。品質・速度は公開接続後に別途実測が必要 |
| Workers Rate Limiting | AI呼び出し制限 | アカウント共有のバインディングで、1つの実行環境のメモリーに依存せず制限。IPごとに1分10回。Cloudflareロケーションごとの制限であり、全世界共通の課金上限ではない。[公式](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) |
| localStorage | 下書き・自作ワード・履歴 | 自分用データを端末内に残し、サーバーのユーザーデータベースを不要にする。端末間同期はできず、サイトデータの削除で失われる |
| Web Speech API | 日本語音声入力と読み上げ | OS/ブラウザの機能を利用し、別の音声SDKを管理しない。対応環境と権限に依存。[音声認識](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、[読み上げ](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis) |
| Node.js標準HTTP / node:test | ローカル実行・自動テスト | 追加インストールなしで画面を動かし、教材・採点・API異常系を検証できる。Cloudflare実環境との接続検証は別途必要 |
| Git / GitHub | 履歴・公開ソース | 変更を差分で確認し、コミット単位で追跡できる。公開対象をこのプロジェクトのソースに限定 |
| Wrangler 4.151.3 | Cloudflare公開CLI | 利用者の承認を得てプロジェクト専用に導入。package-lock.jsonで固定し、再公開の手順を再現できるようにする。認証はアカウント閲覧・Workers公開・AI利用を中心とする6権限に限定 |

## データと採点

通常のルール採点にサーバー通信は必要ありません。キラーワードの一致と採点は別の指標です。具体的な目的・対象・形式・制約・検証の記述を確認し、キーワードを並べただけでは合格しないようにしています。これは意味理解や専門的な正しさの評価ではありません。

AI相談時だけ、現在のお題・条件・プロンプトをCloudflareへ送ります。送信前に画面で説明します。外部音声認識サービスへの送信はブラウザの仕様に依存するため、音声入力前にも説明します。

## 認証を設けなかった理由

今回は自分用で、記録を端末に保存する構成です。ログイン機能は設けず、独自パスワードも保管しません。「Google認証のみ」は参考投稿の教材語として収録しました。クラウドで個人の記録を同期する段階ではGoogle認証とサーバー側のアクセス制御を追加する必要があります。

## AIの利用制限

AI用のキーはブラウザへ渡しません。JSON・同一Origin・最大32KB・プロンプト10〜8,000文字・存在するお題を検査します。レート制限を設定していない環境ではAIを実行しません。AIの応答はテキストとして描画し、HTMLとして実行しません。制限サービス障害・推論失敗・応答なしを画面に伝え、通常の練習は継続できます。

短いコーチ文・追加質問では、Qwen公式が示す`/no_think`を使い、思考だけで出力上限を使い切ることを避けます。途中の思考ブロックだけを回答として表示しません。[Qwen公式モデル説明](https://huggingface.co/Qwen/Qwen3-30B-A3B-FP8#switching-between-thinking-and-non-thinking-mode)
